# 02 Project Structure

An agent cannot read your mind, but it can read your directories. The clearer the structure, the fewer its mistakes.

## Recommended layout

```text
my-project/
├── AGENTS.md          # project notes for the agent
├── README.md          # notes for humans
├── CHANGELOG.md       # feature iterations and bug fixes
├── VALIDATION.md      # validation checklist (see 05)
├── data/
│   ├── raw/           # original data, read-only
│   └── processed/     # generated by scripts, reproducible
├── src/               # reusable code
├── scripts/           # thin entry-point scripts
├── notebooks/         # exploration; move into src/ once stable
├── tests/             # tests on small datasets
├── results/           # results and figures, reproducible
├── envs/              # environment files
├── docs/              # methods, plans, decision records
└── hand_off/          # session hand-off packages (see 08)
```

Full template: [`templates/en/project-layout.md`](../../templates/en/project-layout.md).

## Three habits

1. **Raw data is read-only.** No script or agent touches `data/raw/`. Write cleaned output to `data/processed/`.
2. **Results are reproducible.** `results/` and `data/processed/` should be regenerable by code. Steps that can only be done by hand go in `docs/`.
3. **Scripts are thin entry points.** In `scripts/`, parse arguments, call `src/`, write output. Logic lives in modules, so a change has a small blast radius and is easy to test.

## AGENTS.md

Codex reads the project's `AGENTS.md`. Write: a one-line summary, environment and test commands, directory conventions and **no-go zones**, code style, and the definition of done.
Short and specific beats long and complete. Start from [`templates/en/AGENTS.md`](../../templates/en/AGENTS.md).

Keep names plain too: `data/raw/2026-11-ligands_v1.csv` beats `final_final_new.csv` by a mile, for you, your colleagues and the agent alike.
