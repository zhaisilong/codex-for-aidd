# 05 安全与合规

药物研发的数据往往很敏感。这一章不吓人,只列几件值得先想清楚的事。

## 1. 数据能不能发给云端模型?

使用云端智能体时,你让它读取的文件内容会发送到服务端。动手之前先问自己:

- 这是**未发表**的化合物结构、序列或实验结果吗?
- 涉及**人类受试者**或患者数据吗?
- 所在机构、合作方、合同或伦理审批有没有限制?

不确定就先问你的机构(信息安全或伦理部门),并查看所用服务的数据处理与保留政策。
涉及受试者数据时,以所在机构和法规要求为准。

一个稳妥的做法:用**脱敏样例**或**合成数据**让智能体写代码,真实数据只在本地跑。

## 2. 权限与沙箱

- 刚开始用,选更保守的权限模式(例如只读或只能写工作目录),需要时再放开。
- 谨慎开放网络访问,谨慎允许删除操作。
- 不要在不可信的仓库、陌生脚本上给予宽松权限。
- 具体的权限模式名称和配置方式以官方文档为准。

## 3. 密钥管理

- 密钥放环境变量或密钥管理工具,不写进代码和 `AGENTS.md`
- 不要把 `.env` 提交到仓库
- 如果不小心提交了,立刻作废并更换,仅删除提交是不够的

## 4. 结果核对

智能体可能出错,而且出错时往往语气很自信。几个常见风险:

- **编造引用或数据库字段**:参考文献、数据库名、字段含义,逐一核对
- **统计方法不合适**:检验方法、多重检验校正、数据泄漏,需要有人把关
- **生物学解释过度**:机制推断请对照原始证据
- **静默改变行为**:重构后用测试和小样例对比前后输出

一个简单的清单:

- [ ] 我看过 diff 了吗
- [ ] 测试通过了吗,测试本身合理吗
- [ ] 关键数字我独立算过或抽查过吗
- [ ] 引用和链接我打开确认过吗

## 5. 留下记录

重要分析请保留:使用的提示、关键决策、软件与数据版本。
这既是可复现性的要求,也是以后追责与自查的依据。
