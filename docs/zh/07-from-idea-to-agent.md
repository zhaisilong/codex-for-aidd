# 07 从想法到执行

智能体擅长执行,但"做什么、为什么"要在动手前想清楚。我们的节奏是:**先讨论,再 plan,再执行**。

## 第一步:先把想法聊透

写第一行代码前,先和 Claude 或 ChatGPT(尤其 Pro 的深度推理)讨论:

- idea 要解决什么问题
- 操作细节和每步的输入输出
- 可行性:数据、算力、有没有更简单的做法
- 相关论文读什么,结论和局限是什么

目的是把模糊变清晰,不是产出代码。

## 第二步:把讨论变成文档

整理后放进 `docs/`:目标与背景、方法与步骤、数据说明、验收标准、未决问题。
文档比聊天记录可靠,能进版本控制,也能被智能体反复读取。

## 第三步:开 plan,先对齐

**只要操作不是显而易见的,就先开 plan 模式**(入口见官方文档),让 Codex 先出计划,对齐到你的想法再动手。

```text
请先阅读 docs/plan.md 和 docs/data.md,给我一份实施计划:
分几步、每步改哪些文件、如何验证。先不要改任何文件,等我确认。
```

为什么这么坚持:Codex 有很多"短见",它的超长期上下文和对项目的先验知识都有限。
计划阶段是你把方向、边界和判断交给它的最好时机,看计划时发现的偏差,比事后改代码便宜得多。

## 第四步:一起做

确认计划后,按前几章的编排推进:`AGENTS.md` 配好([01](01-project-structure.md))、小步改动加小测试([02](02-reusable-code.md))、一个任务一个分支([03](03-git-github.md))、验证清单持续更新([05](05-safety.md))。

这是"一起做",不是"交出去"。你负责方向、判断和验收,它负责快速推进。
对话里你对项目的理解会加深,把这些理解回写到文档和 `AGENTS.md` 里,就是 [09](09-growth-and-taste.md) 说的"长出来"。
