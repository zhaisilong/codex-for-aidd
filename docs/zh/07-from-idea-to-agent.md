# 07 从想法到执行

智能体擅长执行,但"做什么、为什么这样做"最好在动手前想清楚。我们习惯把工作分成两段:**先讨论,再执行**。

## 第一段:和对话型模型把想法聊透

在写第一行代码之前,先和 Claude 或 ChatGPT(尤其是 Pro 档的深度推理)聊:

- 这个 idea 到底要解决什么问题
- 操作细节怎么走,每一步的输入输出是什么
- 可行性:数据够不够,算力够不够,有没有更简单的做法
- 相关论文:读什么、各自的结论和局限是什么

这一步的重点是**把模糊变清晰**,不是产出代码。

## 把讨论变成文档

讨论结束后,整理出几份可以交给智能体的文档,放进项目的 `docs/` 里:

- **目标与背景**:一段话说明要做什么、为什么
- **方法与步骤**:关键步骤、使用的工具和参数
- **数据说明**:数据在哪里、什么格式、哪些不能动
- **验收标准**:怎样算做对了,用什么测试或指标检查
- **未决问题**:你自己也还不确定的地方

文档比聊天记录可靠:它能进版本控制,也能被智能体反复读取。

## 第二段:交给智能体,一起做

把文档和**允许共享的数据**交给 Codex(数据是否可以发送,先看 [05 安全与合规](05-safety.md))。这时要遵循前面几章的工程编排:

- 目录与 `AGENTS.md` 先配好([01](01-project-structure.md))
- 原始数据只读,结果可再生
- 小步改动,配小测试([02](02-reusable-code.md))
- 一个任务一个分支,自己看 diff([03](03-git-github.md))
- 难度合适的思考深度([06](06-reasoning-and-models.md))

### 一个开场示例

```text
请先阅读 docs/plan.md 和 docs/data.md。
然后给我一份实施计划:分几步、每步改哪些文件、如何验证。
先不要修改任何文件,等我确认后再开始。
```

确认计划后,再让它一步步做,每一步都要求跑测试、给 diff 摘要。

## 是"一起做",不是"交出去"

智能体不是外包。你负责方向、判断和验收,它负责把事情快速推进。
在它做的过程中,你对项目的理解会加深,这些理解要回写到文档和 `AGENTS.md` 里,
这也是下一章讲的"项目是长出来的"。
