## 两种计费思路

| | 订阅制 | API 按量计费 |
|---|---|---|
| 适合 | 日常交互式开发 | 批量自动化、集成到流水线 |
| 成本特点 | 相对可预期,有用量上限 | 用多少付多少,需要自己控预算 |
| 注意 | 高强度使用可能触顶 | 设置预算上限和告警 |

## 怎么挑档位

用一个简单的决策方式:

- **偶尔用、主要写小脚本** → 入门档位足够
- **每天重度开发、多个项目并行** → 选更高档位,避免被限额打断
- **要跑批量任务或接入自己的流水线** → 用 API,并设置预算上限

先用低档,**真的撞到限额**再升级,通常比一开始买满更划算。

## 怎么用模型更省

- **规划用强模型,苦力活用轻量模型**:格式化、批量改名、补 docstring 这类任务不需要最强的。
- **控制上下文**:别一次性喂整个大数据目录;告诉它只看哪些文件。
- **任务拆小**:长对话会不断累积上下文,拆成多个短任务通常更省也更准。
- **先计划后动手**:避免走错方向后整段推倒重来。
- **别让它读大文件**:大表格、大序列文件请让它写脚本去处理,而不是把内容读进对话。
