# 05 安全与结果核对

## 数据能不能发给云端?

使用云端智能体时,它读取的文件内容会发送到服务端。动手前问自己:

- 是**未发表**的化合物、序列或实验结果吗?
- 涉及**人类受试者**或患者数据吗?
- 机构、合作方、合同或伦理审批有限制吗?

不确定就先问机构的信息安全或伦理部门,并看所用服务的数据处理与保留政策。
稳妥做法:让智能体用**脱敏样例或合成数据**写代码,真实数据只在本地跑。

## 权限与密钥

- 刚开始用保守的权限模式(只读或只能写工作目录),需要时再放开;谨慎开放网络和删除。
- 不在不可信的仓库上给宽松权限。
- 密钥放环境变量,不写进代码和 `AGENTS.md`,不提交 `.env`。

## 结果核对

智能体出错时语气往往很自信。常见风险:

- 编造引用、数据库名或字段含义
- 统计方法不合适(检验选择、多重检验校正、数据泄漏)
- 生物学解释过度
- 重构后行为悄悄改变

### 验证清单:让 agent 维护

在项目根目录放一份 `VALIDATION.md`,把"怎样算做对了"写成带状态的清单,**经常让 agent 去维护和校验**。
这样你随时一眼看到进度,哪些通过、哪些没做、哪些有问题。

建议这样用:

1. 项目开始时,让 agent 根据任务起草清单,你审定
2. 每完成一个阶段,让它逐条运行检查,更新状态和日期
3. 失败项写明原因,别删掉

AIDD / 生信常见检查项:

- SMILES 已标准化并去重,无效结构有记录
- 训练/测试划分无泄漏(骨架、序列相似度、时间)
- 随机种子、软件版本、数据校验和已记录
- 基线对比和统计检验合理,有置信区间
- 对接、打分的单位、坐标系、质子化状态一致
- 引用和链接逐一打开确认过

模板:[`templates/VALIDATION.md`](../../templates/VALIDATION.md)。

## 留下记录

重要分析保留关键决策、软件与数据版本。这既是可复现性的要求,也是以后自查的依据。
