# 03 Git 与 GitHub

版本控制是你给智能体系的安全绳。出了问题,一条命令就能退回去。

## 基本节奏

1. 开始前,确认工作区是干净的(`git status`)
2. 一个任务一个分支
3. 让 Codex 小步改动,你自己看 `git diff`
4. 满意了再提交,提交信息写清楚做了什么
5. 通过 Pull Request 合并,哪怕只有你一个人

让智能体帮忙写提交信息可以,但**diff 一定要自己过一遍**。

## 提交的粒度

- 一次提交只做一件事
- 重构和功能改动分开提交
- 大范围的格式化单独提交,避免淹没真正的改动

## 什么不该进仓库

| 类型 | 做法 |
|---|---|
| 密钥、令牌、账号密码 | 放环境变量,绝不提交 |
| 大体积数据、模型权重 | 用 Git LFS、DVC 或外部存储,仓库里只放获取方式 |
| 未发表的化合物结构、受试者数据 | 默认不上传,先看 [05 安全与合规](05-safety.md) |
| 可再生的中间结果 | 加入 `.gitignore` |

可从 [`templates/gitignore`](../../templates/gitignore) 开始。

## 给分析打标签

论文、报告里用到的那一版分析,打一个 tag(例如 `v1.0-paper`),
并在文档里写明对应的数据版本和环境。几个月后审稿人问起来,你能秒回。

## 小提醒

- 如果智能体改了你没预期的文件,先别提交,问它为什么,必要时 `git restore` 回退。
- 公开仓库提交前,再检查一遍有没有混入路径、邮箱、内部数据。
