# 06 思考深度与模型选择

同一个模型,思考深度不同,速度、成本和结果都会不同。这一章是我们日常使用的经验。

> 档位名称和可用性会随版本变化,请以 Codex 里 `/model` 选择器显示的为准。核对日期:2026-11-25。

## 档位一览

| 档位 | 说明 |
|---|---|
| Low(桌面版叫 Light) | 最快,适合很小的改动 |
| Medium | **默认档位** |
| High | 日常开发、一般调试 |
| Extra high(xhigh) | **我们的主力档** |
| Max | 最深的单线程思考 |
| Ultra | 并行:用子智能体同时处理任务的不同部分 |

- Max 和 Ultra 在某些版本里需要在设置中开启后才会出现。
- 可以在 `/model` 里切换,也可以在 `config.toml` 里用 `model_reasoning_effort` 设置默认值(具体写法以官方文档为准)。

## 我们怎么用

### Extra high:日常主力

大多数认真的开发和分析工作,用 Extra high 就好:复杂逻辑、重构、流程设计、反复出错的问题。

**如果你有 Pro $100 及以上的账号,推荐 Extra high 一直开着用**,省得每次切换,体验最稳定。

如果没有,就按问题难度切换:

- 改名、格式化、补注释、写小脚本 → Low / Medium
- 日常开发和一般调试 → High
- 复杂设计、重构、棘手的 bug → Extra high
- 特别深的问题 → 偶尔用 Max

### Ultra:开局和大面积探索

Ultra 的特点是**并行**,它会用多个子智能体同时做不同的事。我们喜欢在这些时候用:

- **项目刚开始**,需要快速搭起骨架、同时探索多个方向
- **大面积的快速探索**,例如同时看几个数据库、几种方法
- **需要同步写代码**,不同模块可以并行推进

注意事项:

- 并行意味着 token 和额度消耗会成倍增加,有社区实测报告同类任务消耗约 2.5 倍,仅供参考。
- 任务能被拆成相对独立的几块时,Ultra 才划算;紧密耦合的问题,并行帮不上忙。
- 并行写代码更需要好的目录和边界,见 [01 项目目录与脚本](01-project-structure.md)。

### Max:让它阻塞地深想

Max 是思考最深的一档,最适合**单线程、阻塞式**地使用:

1. **只开这一个任务**,不要同时让它做别的。
2. **先把材料摆到它眼前**:相关结果、日志、数据摘要、关键代码、论文要点,最好整理进文件。
3. **再给一个清晰的 prompt**:要回答什么问题、有哪些约束、希望得到什么形式的输出。
4. **然后等**。让它想透,而不是中途不断打断。

可以把它理解为"请一位专家关起门来想一个下午"。材料越齐,值得越高。

## 模型怎么选

- **主力用 Sol 或 Terra**。价格合理,能力足够覆盖绝大多数工作。
- **Astra 太贵**,不到万不得已不推荐:Sol 反复失败、问题极难、出错代价极高时再用。
- **一般直接用最新的模型**。不同代的价格差不多,新模型通常体验更好。
- 具体价格见 [04 模型选择与价格](04-models-and-pricing.md)。

## 一个小对照

| 场景 | 模型 | 档位 |
|---|---|---|
| 给脚本补 docstring | Terra | Low / Medium |
| 把 notebook 重构为模块 | Sol | Extra high |
| 项目开局,同时搭骨架和探索方法 | Sol | Ultra |
| 排查一个复杂的数值不一致问题(材料已备齐) | Sol | Max |
| 前面都失败了的难题 | Astra | Extra high / Max |

这只是起点,请根据自己的额度和经验调整。
