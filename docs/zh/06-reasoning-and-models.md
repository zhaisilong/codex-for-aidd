# 06 思考深度与模型选择

> 档位名称和可用性随版本变化,以 Codex 里 `/model` 显示为准。核对日期:2026-11-25。

## 档位

| 档位 | 说明 |
|---|---|
| Low(桌面版叫 Light)| 最快,小改动 |
| Medium | 默认 |
| High | 日常开发、一般调试 |
| **Extra high** | **主力档** |
| Max | 最深的单线程思考 |
| Ultra | 并行:子智能体同时处理任务的不同部分 |

Max 和 Ultra 在某些版本里需要先在设置中开启。默认值可在 `config.toml` 用 `model_reasoning_effort` 设置(以官方文档为准)。

## 我们怎么用

**Extra high:日常主力。** 复杂逻辑、重构、流程设计、反复出错的问题。
**有 Pro $100 以上账号,Extra high 开到底、一直用就好**,省得切换。否则按难度切换:小活 Low/Medium,日常 High,难题 Extra high,偶尔 Max。

**Ultra:开局和大面积探索。** 它并行工作,适合:
- 项目刚开始,快速积累原始代码、同时探索几个方向
- 大面积快速探索(几个数据库、几种方法)
- 需要同步写代码、模块可并行推进

并行会成倍消耗额度(社区一例实测约 2.5 倍,仅供参考),任务能拆成相对独立的几块才划算。

**Max:单线程、阻塞式深想。**
1. 只开这一个任务,不同时做别的
2. 先把材料摆到它眼前:结果、日志、数据摘要、关键代码、论文要点,整理进文件
3. 再给一个清晰的 prompt:问什么、有何约束、要什么形式的输出
4. 然后等,别中途打断

像请专家关起门想一个下午,材料越齐越值。

## 梯度调用

不同阶段用不同档位和模型,是最省也最稳的做法:

| 阶段 | 模型 | 档位 |
|---|---|---|
| 开局,快速积累原始代码 | Sol | Ultra |
| 后续开发、重构 | Sol | Extra high |
| 部署、GitHub 更新等杂活 | Terra | Medium / High |

具体怎么拆 session,见 [08](08-sessions-and-handoff.md)。

## 模型怎么选

- 主力 **Sol / Terra**;**Astra 太贵**,Sol 反复失败、问题极难、出错代价极高时才用
- 一般直接用最新模型,价格差不多
- 价目表见 [07](07-pricing.md)
