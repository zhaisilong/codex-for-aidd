# 02 代码细节与复用

智能体写代码很快,但"快"也意味着重复代码会成倍增加。这一章讲怎么让代码留得住、用得上。

## 从一次性脚本到可复用模块

一个常见的演化路径:

1. 在 notebook 或临时脚本里探索
2. 结果靠谱后,把核心逻辑提取成函数,放进 `src/`
3. 脚本只负责参数和输入输出
4. 给函数配一个小测试

可以直接这样对 Codex 说:

```text
把 notebooks/dock_analysis.ipynb 中处理对接结果的部分提取为 src/docking/parse.py 里的函数,
保持行为不变,并在 tests/ 下用一个小样例写测试。先给我计划,不要直接改。
```

## 让代码更容易被智能体正确修改

- **函数小而单一**:一个函数做一件事,智能体改动时不容易牵连别处。
- **写类型标注和 docstring**:尤其是输入输出的含义、单位、坐标系、SMILES 是否已标准化等。
- **避免魔法数字**:阈值、截断值放到配置里并写明来源。
- **别把路径写死**:用参数或配置文件,不要在代码里写 `/home/xxx/`。

## 测试:小而够用

生信和 AIDD 的数据往往很大,但测试不需要大数据:

- 准备 3~10 条有代表性的**小样例**放进 `tests/data/`
- 覆盖正常情况和边界情况(空输入、非法 SMILES、缺失列)
- 让 Codex "改完必须跑通测试"

测试是你和智能体之间最便宜的契约。

## 可复现性的几个细节

- 固定随机种子,并把种子写进输出的元数据
- 记录关键软件版本(RDKit、PyTorch、Scanpy 等)
- 记录数据版本或校验和
- 环境文件(`environment.yml`、`pyproject.toml` 等)随代码一起提交

## 别忘了删

让智能体做完重构后,问一句:"有没有因此变成无用的文件或函数?"
长期来看,删代码和写代码一样重要。
